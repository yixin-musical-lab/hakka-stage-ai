# 客韵智演：阿里云轻量应用服务器部署指南（Caddy，HTTP 起步 / HTTPS 生产）

> 更新日期：2026-07-23
> 适用版本：已接入 `wan2.7-i2v-2026-04-25` 的版本；部署时使用对应代码提交的镜像标签
> 适用场景：阿里云轻量应用服务器、Ubuntu 22.04 / 24.04、单机 Docker Compose；可先用公网 IP + HTTP 验证 Mock，真实 Wan 回源使用域名 + HTTPS

## 1. 部署目标与边界

本文档把项目部署为以下结构：

```text
浏览器 / 阿里云百炼
        |
        | HTTP 80
        v
      Caddy
        |-- 页面及静态资源 --> frontend:80
        `-- /api/*、/health --> backend:8000
                                  |-- PostgreSQL
                                  |-- Redis
                                  `-- MinIO 私有对象存储
```

Caddy 在这里仅作为 HTTP 公网入口和反向代理，不申请 SSL 证书。公网只开放 `22` 和 `80` 端口；后端、数据库、Redis 和 MinIO API 均不直接暴露到公网。

部署完成后：

- 页面通过 `http://服务器公网IP` 访问；
- 前端和 API 使用同一来源，前端通过 `/api` 请求后端；
- Mock 阶段可使用 `VIDEO_PUBLIC_BASE_URL=http://服务器公网IP`；真实调用建议改为域名 HTTPS；
- 本地上传的 Wan 首帧先写入私有 MinIO，再由后端生成两小时有效的临时公网地址，供百炼回源；
- 首次启动先开启视频 Mock 模式验证全链路，确认正常后再填写真实 DashScope API Key。

> [!WARNING]
> 当前系统尚未完成复杂权限、班级隔离和业务数据按账号隔离，不应上传真实敏感学生视频。HTTP 也无法加密登录信息和临时图片令牌，只适合短期演示与受控测试。正式使用前应绑定域名并迁移到 HTTPS。

## 2. 准备服务器

### 2.1 建议配置

- 系统：Ubuntu 24.04 x86_64，Ubuntu 22.04 也可；
- 最低演示配置：2 核 CPU、4 GB 内存；
- 更稳妥配置：4 核 CPU、8 GB 内存、60 GB 以上系统盘；
- 本项目的视频生成发生在第三方云端，不要求服务器配置 GPU；
- 服务器磁盘还需要容纳 PostgreSQL、MinIO 上传文件和容器镜像。

### 2.2 配置阿里云防火墙

在阿里云轻量应用服务器控制台中，仅放行：

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| `22` | TCP | SSH 登录 |
| `80` | TCP | Caddy HTTP 入口 |

暂时不要开放：

- `443`：当前未启用 HTTPS；
- `5173`：本地 Vite 开发端口；
- `8000`：FastAPI 后端端口；
- `5432`：PostgreSQL；
- `6379`：Redis；
- `9000`：MinIO API；
- `9001`：MinIO 管理控制台。

记录服务器公网 IP，后续把文档中的 `服务器公网IP` 替换为真实值。以下示例假设公网 IP 为 `47.100.20.30`，不要原样照抄该示例地址。

## 3. 登录服务器并安装基础工具

从本机连接服务器：

```bash
ssh root@服务器公网IP
```

更新索引并安装工具：

```bash
sudo apt update
sudo apt install -y ca-certificates curl git gnupg openssl
```

检查系统架构和版本：

```bash
uname -m
. /etc/os-release && echo "$PRETTY_NAME"
```

预期架构为 `x86_64`。

## 4. 使用阿里云软件源安装 Docker

中国大陆网络访问 Docker 官方站点时可能出现 `Connection reset by peer`。以下步骤使用阿里云 Docker CE Ubuntu 镜像，但仍采用 Docker 官方签名密钥校验软件包。

创建密钥目录：

```bash
sudo install -m 0755 -d /etc/apt/keyrings
```

下载 Docker GPG 密钥：

```bash
sudo curl -4 -fL --retry 5 --retry-delay 2 https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

检查密钥文件：

```bash
head -n 1 /etc/apt/keyrings/docker.asc
```

预期输出：

```text
-----BEGIN PGP PUBLIC KEY BLOCK-----
```

配置 Docker CE 软件源：

```bash
sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<EOF
Types: deb
URIs: https://mirrors.aliyun.com/docker-ce/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
```

安装 Docker Engine 和 Compose 插件：

```bash
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
```

检查版本：

```bash
sudo docker version
sudo docker compose version
```

## 5. 配置 Docker Hub 镜像加速器

APT 软件源只解决 Docker 软件安装，不能解决 Docker Hub 镜像拉取问题，二者不是同一个配置。虽然本文后续会让 PostgreSQL、Redis 和 MinIO 使用其他官方 Registry，仍建议配置 Docker Hub 加速器，用于 Caddy、基础连通测试以及其他 Docker 官方镜像。

### 5.1 获取阿里云专属加速地址

1. 登录[阿里云容器镜像服务控制台](https://cr.console.aliyun.com/)；
2. 进入“容器镜像服务 ACR”；
3. 选择“镜像工具” -> “镜像加速器”；
4. 复制形如 `https://xxxxxxxx.mirror.aliyuncs.com` 的专属地址。

不要使用本文示例中的 `xxxxxxxx`。

### 5.2 写入 Docker 配置

先设置当前终端变量，替换为自己的真实地址：

```bash
export HAKKA_DOCKER_MIRROR='https://xxxxxxxx.mirror.aliyuncs.com'
echo "$HAKKA_DOCKER_MIRROR"
```

备份可能已有的配置：

```bash
sudo mkdir -p /etc/docker
sudo cp -a /etc/docker/daemon.json "/etc/docker/daemon.json.bak.$(date +%Y%m%d-%H%M%S)" 2>/dev/null || true
```

如果这是全新安装，可写入：

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<EOF
{
  "registry-mirrors": [
    "$HAKKA_DOCKER_MIRROR"
  ]
}
EOF
```

> [!IMPORTANT]
> 如果 `/etc/docker/daemon.json` 原来已有其他有效配置，不要直接覆盖，应把 `registry-mirrors` 合并到原 JSON 中。

重启并检查 Docker：

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
sudo systemctl --no-pager --full status docker
sudo docker info | sed -n '/Registry Mirrors/,+3p'
```

测试 Docker Hub 拉取：

```bash
sudo docker run --rm hello-world
```

看到 `Hello from Docker!` 才表示 Docker Hub 加速配置可用。如果仍出现 `registry-1.docker.io` 超时，先不要继续部署，检查专属加速地址是否填写正确。

> [!NOTE]
> 阿里云 Docker Hub 加速器可能对某些确实存在的标签错误返回 `not found`。本项目的生产覆盖文件因此不再通过 Docker Hub 拉取 PostgreSQL、Redis 和 MinIO：PostgreSQL、Redis 改用 Amazon ECR Public 上的 Docker 官方镜像副本，MinIO 改用其官方 Quay 仓库。Docker Hub 加速器仍可用于 `hello-world` 等基础连通测试。

## 7. 创建服务器环境变量

先生成三个随机值并保存到安全位置：

```bash
openssl rand -hex 32
openssl rand -hex 24
openssl rand -hex 24
```

三个输出分别用于：

1. `AUTH_SECRET_KEY`；
2. `POSTGRES_PASSWORD`；
3. `MINIO_SECRET_KEY`。

从示例文件创建 `.env`：

```bash
cd /opt/hakka-stage-ai
cp .env.example .env
nano .env
```

至少确认或修改以下项目。所有 `请替换` 内容都必须替换，公网 IP 不带结尾斜杠：

```dotenv
# 使用第 6 节记录的目标短提交号，确保代码与三个镜像一致
IMAGE_TAG=sha-目标短提交号

# 数据库
POSTGRES_DB=hakka_stage_ai
POSTGRES_USER=hakka
POSTGRES_PASSWORD=请替换为第二个随机值

# MinIO 私有对象存储
MINIO_ACCESS_KEY=hakkaadmin
MINIO_SECRET_KEY=请替换为第三个随机值
MINIO_BUCKET=hakka-stage-ai
MINIO_BROWSER_REDIRECT_URL=http://127.0.0.1:9001

# 登录与浏览器访问
AUTH_SECRET_KEY=请替换为第一个随机值
AUTH_ACCESS_TOKEN_MINUTES=480
AUTH_COOKIE_SECURE=false
CORS_ORIGINS=http://服务器公网IP
VITE_API_BASE_URL=/

# 全新数据库第一次启动时创建管理员账号
BOOTSTRAP_ACCOUNT_EMAIL=请替换为管理员邮箱
BOOTSTRAP_ACCOUNT_PASSWORD=请替换为强初始密码
BOOTSTRAP_ACCOUNT_DISPLAY_NAME=平台管理员
BOOTSTRAP_ACCOUNT_ROLE=teacher

# 大模型先使用 Mock，避免首次启动产生费用
LLM_MOCK_MODE=true
MEDIA_MOCK_MODE=true

# 阿里云百炼 Wan 2.7 图生视频：首次启动先验证 Mock 链路

# GRS AI 仅继续用于媒体工作台图生图；MEDIA_MOCK_MODE=true 时可暂时留空
GRSAI_API_KEY=
GRSAI_BASE_URL=https://grsai.dakka.com.cn
```

例如公网 IP 是 `47.100.20.30` 时：

```dotenv

VIDEO_PUBLIC_BASE_URL=http://47.100.20.30
```

检查 `.env` 不会被 Git 跟踪：

```bash
git check-ignore .env
```

预期输出 `.env`。不要把 `.env`、API Key、数据库密码或初始化密码提交到 Git。

## 8. 创建生产 Compose 覆盖文件

仓库根目录的 `docker-compose.yml` 面向本地开发，会构建源码并公开多个开发端口。服务器通过覆盖文件改用已发布的生产镜像，并移除不必要的宿主机端口。

创建文件：

```bash
nano /opt/hakka-stage-ai/compose.production.yml
```

写入：

```yaml
services:
  postgres:
    # ECR Public 提供 Docker 官方 PostgreSQL 镜像副本，避开 Docker Hub 加速器错误缓存。
    image: public.ecr.aws/docker/library/postgres:16-alpine
    # 数据库仅允许 Docker 内部网络访问。
    ports: !override []

  redis:
    # ECR Public 提供 Docker 官方 Redis 镜像副本，避开 Docker Hub 加速器错误缓存。
    image: public.ecr.aws/docker/library/redis:7-alpine
    # Redis 仅允许 Docker 内部网络访问。
    ports: !override []

  minio:
    # 使用 MinIO 官方 Quay 仓库；该固定版本与仓库当前配置一致。
    image: quay.io/minio/minio:RELEASE.2025-04-22T22-12-26Z
    # MinIO API 不公开；管理控制台只绑定服务器回环地址。
    ports: !override
      - "127.0.0.1:9001:9001"

  backend:
    # 清除本地源码构建配置，使用与代码提交对应的 GHCR 镜像。
    build: !reset null
    image: ghcr.io/yixin-musical-lab/hakka-stage-ai-backend:${IMAGE_TAG:?请先在 .env 设置 IMAGE_TAG}
    ports: !override []

  worker:
    build: !reset null
    image: ghcr.io/yixin-musical-lab/hakka-stage-ai-worker:${IMAGE_TAG:?请先在 .env 设置 IMAGE_TAG}

  frontend:
    build: !reset null
    image: ghcr.io/yixin-musical-lab/hakka-stage-ai-frontend:${IMAGE_TAG:?请先在 .env 设置 IMAGE_TAG}
    ports: !override []
    # 生产前端基于 Nginx，不再使用开发镜像中的 Node 健康检查。
    healthcheck:
      test: ["CMD", "wget", "--quiet", "--output-document=-", "http://127.0.0.1/healthz"]
      interval: 10s
      timeout: 5s
      retries: 5

  caddy:
    image: caddy:2-alpine
    container_name: hakka-stage-ai-caddy
    restart: unless-stopped
    ports:
      - "80:80"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      backend:
        condition: service_healthy
      frontend:
        condition: service_healthy

volumes:
  caddy_data:
  caddy_config:
```

`!reset` 和 `!override` 需要较新的 Docker Compose。当前部署过程中已确认的 Compose `v5.3.1` 支持该语法。

## 9. 创建纯 HTTP Caddy 配置

创建文件：

```bash
nano /opt/hakka-stage-ai/Caddyfile
```

写入：

```caddyfile
:80 {
    # API、公开 Wan 图片回源地址和健康检查统一转发到 FastAPI。
    @backend path /api/* /health
    handle @backend {
        reverse_proxy backend:8000
    }

    # 其余请求交给生产前端容器处理。
    handle {
        reverse_proxy frontend:80
    }
}
```

使用 `:80` 而不是域名，可以明确只监听 HTTP，Caddy 不会申请证书，也不会自动跳转 HTTPS。

## 10. 校验并启动全部服务

进入项目目录：

```bash
cd /opt/hakka-stage-ai
```

先验证 Compose 合并结果：

```bash
sudo docker compose -f docker-compose.yml -f compose.production.yml config --quiet
```

检查生产配置中不应公开内部端口：

```bash
sudo docker compose -f docker-compose.yml -f compose.production.yml config | sed -n '/ports:/,+8p'
```

检查合并后的实际镜像地址：

```bash
sudo docker compose -f docker-compose.yml -f compose.production.yml config --images
```

其中应包含：

```text
public.ecr.aws/docker/library/postgres:16-alpine
public.ecr.aws/docker/library/redis:7-alpine
quay.io/minio/minio:RELEASE.2025-04-22T22-12-26Z
ghcr.io/yixin-musical-lab/hakka-stage-ai-backend:sha-目标短提交号
ghcr.io/yixin-musical-lab/hakka-stage-ai-worker:sha-目标短提交号
ghcr.io/yixin-musical-lab/hakka-stage-ai-frontend:sha-目标短提交号
```

如果前三项仍显示 `docker.io/library/postgres`、`docker.io/library/redis` 或 `docker.io/minio/minio`，说明 `compose.production.yml` 的镜像覆盖没有正确写入，不应继续拉取。

拉取镜像：

```bash
sudo docker compose -f docker-compose.yml -f compose.production.yml pull
```

Compose 会并行拉取镜像。某个镜像失败后，其他镜像可能显示 `Interrupted`；这通常只是被连带中断，不代表这些镜像或标签有问题。修复真正显示 `Error` 的镜像后，重新运行同一条 `pull` 命令即可复用已下载的镜像层。

启动：

```bash
sudo docker compose -f docker-compose.yml -f compose.production.yml up -d --no-build
```

查看状态：

```bash
sudo docker compose -f docker-compose.yml -f compose.production.yml ps
```

正常情况下应看到以下服务运行，带健康检查的服务最终为 `healthy`：

- `postgres`；
- `redis`；
- `minio`；
- `backend`；
- `worker`；
- `frontend`；
- `caddy`。

首次启动较慢时，查看日志而不是反复重建：

```bash
sudo docker compose -f docker-compose.yml -f compose.production.yml logs --tail=200 backend worker frontend caddy
```

1. 阿里云轻量服务器防火墙是否放行 `80/TCP`；

4. 是否把浏览器地址误写为 `https://`。

## 13. 验证 Wan 2.7 本地图片上传

### 13.1 先验证 Mock 模式

初次启动保持：

```dotenv
DASHSCOPE_API_KEY=
VIDEO_PUBLIC_BASE_URL=http://服务器公网IP
VIDEO_MOCK_MODE=true
```

进入 Wan 视频工作台：

1. 确认“本地上传”按钮可点击；
2. 上传一张不敏感的 JPG、PNG 或 WEBP 图片；
3. 输入短提示词；
4. 创建一条 Mock 任务；
5. 确认上传、MinIO 保存和页面任务状态链路正常。

Mock 模式不会调用真实 Wan，也不会产生第三方生成费用。

### 13.2 切换真实阿里云百炼

编辑 `.env`：

```bash
nano /opt/hakka-stage-ai/.env
```

修改：

```dotenv
DASHSCOPE_API_KEY=请填写视频服务专用的真实密钥
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com
VIDEO_PUBLIC_BASE_URL=https://你的域名
VIDEO_MOCK_MODE=false
```

重建读取这些变量的容器：

```bash
cd /opt/hakka-stage-ai
sudo docker compose -f docker-compose.yml -f compose.production.yml up -d --no-build --force-recreate backend worker
```

真实 Wan 任务前，请先按第 18 节完成域名 HTTPS。再次打开视频工作台，用一张不敏感的小图创建一条 `wan2.7-i2v-2026-04-25`、`720P`、5 秒的冒烟任务，不要一开始批量生成。

真实模式下，后端生成的图片地址形如：

```text
https://你的域名/api/public/media-studio/veo-inputs/临时令牌
```

该路由由 Caddy 转发到后端，后端验证临时令牌后从私有 MinIO 读取图片。MinIO 本身不需要公开。

> [!NOTE]
> 项目代码仍接受可公网访问的 HTTP 地址，但生产环境的 `VIDEO_PUBLIC_BASE_URL` 应使用 HTTPS，避免百炼回源被中间人篡改或供应商策略拒绝。

```bash
sudo docker stats --no-stream
```

> [!CAUTION]
> 不要执行 `docker compose down -v`。`-v` 会删除 PostgreSQL、Redis、MinIO 和 Caddy 数据卷，可能造成不可恢复的数据丢失。

## 15. 备份建议

部署完成并验证后，先在阿里云控制台创建一次服务器快照。之后至少定期备份 PostgreSQL，并根据实际素材价值备份 MinIO 数据。

创建数据库备份目录：

```bash
sudo mkdir -p /opt/hakka-stage-ai/backups
sudo chown -R "$USER":"$USER" /opt/hakka-stage-ai/backups
```

导出 PostgreSQL：

```bash
cd /opt/hakka-stage-ai
sudo docker compose -f docker-compose.yml -f compose.production.yml exec -T postgres pg_dump -U hakka -d hakka_stage_ai | gzip > "backups/postgres-$(date +%Y%m%d-%H%M%S).sql.gz"
```

确认备份文件不是空文件：

```bash
ls -lh backups/
gzip -t backups/postgres-*.sql.gz
```

数据库导出不能替代 MinIO 文件备份和阿里云磁盘快照。

基本流程：

```bash
git status --short
git fetch --prune origin

```

确认目标提交及镜像已经发布后：

然后执行：

## 17. 常见故障排查

### 17.1 Docker 安装时连接被重置

错误示例：

```text
curl: (35) Recv failure: Connection reset by peer
```

确认下载地址使用：

```text
https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg
```

不要继续反复访问 `download.docker.com`。

### 17.2 Docker Hub 超时或错误返回 `not found`

错误示例：

```text
failed to resolve reference "docker.io/..."
dial tcp ...:443: i/o timeout
```

检查：

```bash
sudo cat /etc/docker/daemon.json
sudo docker info | sed -n '/Registry Mirrors/,+3p'
sudo journalctl -u docker -n 50 --no-pager
```

注意：阿里云 APT 镜像不是 Docker Hub 镜像加速器，必须完成本文第 5 节。

如果错误是：

```text
docker.io/library/redis:7-alpine: not found
docker.io/library/postgres:16-alpine: not found
docker.io/minio/minio:RELEASE.2025-04-22T22-12-26Z: not found
```

这些标签本身存在，通常是 Docker Hub 加速器未同步或错误缓存。不要为了绕过错误随意升级数据库或对象存储版本，先检查生产覆盖是否使用了本文指定的 ECR Public 和 Quay 地址：

```bash
sudo docker compose -f docker-compose.yml -f compose.production.yml config --images
```

也可以分别验证替代官方仓库：

```bash
sudo docker pull public.ecr.aws/docker/library/redis:7-alpine
sudo docker pull public.ecr.aws/docker/library/postgres:16-alpine
sudo docker pull quay.io/minio/minio:RELEASE.2025-04-22T22-12-26Z
```

全部成功后重新执行 Compose 拉取。无需删除已下载镜像，也不要删除数据卷。

### 17.3 ECR Public 或 Quay 拉取失败

先测试 Registry 网络：

```bash
curl -I --max-time 15 https://public.ecr.aws/v2/
curl -I --max-time 15 https://quay.io/v2/
```

Registry 根路径可能返回 `401 Unauthorized`，这仍说明 DNS、TCP 和 TLS 已经连通。真正的网络故障通常表现为 DNS 失败、连接重置或超时。如果单独 `docker pull` 仍失败，保留完整错误信息，不要连续更换未知第三方镜像源。

### 17.4 GHCR 拉取失败

阿里云 Docker Hub 加速器通常只代理 Docker Hub，不代理 `ghcr.io`。先测试：

```bash
curl -I --max-time 15 https://ghcr.io/v2/
sudo docker pull ghcr.io/yixin-musical-lab/hakka-stage-ai-backend:sha-目标短提交号
```

`curl` 返回 `401 Unauthorized` 也说明网络已经连通，因为 Registry API 本身需要鉴权；真正异常是 DNS、连接重置或超时。若公共包提示无权限，可登录 GHCR 后再拉取；若服务器网络无法连接 GHCR，则需要在能访问 GHCR 的机器上 `docker pull` 和 `docker save`，再通过 `scp` 上传并 `docker load`，不要误以为 Docker Hub 加速器会自动解决 GHCR 网络问题。

### 17.5 Caddy 启动失败

```bash
sudo docker compose -f docker-compose.yml -f compose.production.yml logs --tail=100 caddy
sudo docker compose -f docker-compose.yml -f compose.production.yml config --quiet
```

重点检查 `Caddyfile` 是否位于仓库根目录、是否误用了全角符号，以及 `80` 端口是否被其他进程占用：

```bash
sudo ss -lntp | grep ':80'
```

### 17.6 页面能打开但无法登录或调用 API

检查 `.env`：

```dotenv
CORS_ORIGINS=http://服务器公网IP
AUTH_COOKIE_SECURE=false
VITE_API_BASE_URL=/
```

然后重建后端：

```bash
sudo docker compose -f docker-compose.yml -f compose.production.yml up -d --no-build --force-recreate backend
```

### 17.7 Wan“本地上传”按钮不可用

真实模式必须同时满足：

```dotenv
DASHSCOPE_API_KEY=已填写真实密钥
VIDEO_PUBLIC_BASE_URL=https://你的域名
VIDEO_MOCK_MODE=false
```

Mock 联调则可使用：

```dotenv
VIDEO_MOCK_MODE=true
```

修改后重建后端，并查看日志：

```bash
sudo docker compose -f docker-compose.yml -f compose.production.yml up -d --no-build --force-recreate backend
sudo docker compose -f docker-compose.yml -f compose.production.yml logs --tail=100 backend
```

### 17.8 Mock 正常但真实 Wan 无法读取图片

按顺序检查：

1. `VIDEO_PUBLIC_BASE_URL` 是否为公网 HTTPS 域名，而不是 `localhost`、`127.0.0.1` 或 Docker 服务名；
2. 公网 `80/TCP`、`443/TCP` 是否放行；
3. Caddy 是否把 `/api/*` 转发到 `backend:8000`；
4. Caddy 证书是否已签发，且公网可直接访问带临时令牌的回源地址；
5. `DASHSCOPE_BASE_URL` 是否误填了 Qwen 的 `/compatible-mode/v1` 路径，或 API Key 与 Endpoint 是否属于不同地域。

如果以上项目均正确，请再在百炼控制台核对任务失败码、模型权限和账户额度。

## 18. 后续迁移到 HTTPS

以后有域名时，无需购买传统 SSL 证书。域名解析到服务器、放行 `443/TCP` 后，可让 Caddy自动申请并续期公开可信证书。

把 `Caddyfile` 的站点地址从：

```caddyfile
:80 {
```

改为：

```caddyfile
your-domain.example.com {
```

同时修改 `.env`：

```dotenv
CORS_ORIGINS=https://your-domain.example.com
AUTH_COOKIE_SECURE=true
VIDEO_PUBLIC_BASE_URL=https://your-domain.example.com
```

并在 `compose.production.yml` 的 Caddy 端口中增加：

```yaml
ports:
  - "80:80"
  - "443:443"
  - "443:443/udp"
```

重新校验并启动后，Caddy 会负责证书申请、HTTP 跳转 HTTPS 和后续自动续期。
